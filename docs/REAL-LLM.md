# 真实模型验收（deepseek-chat · 2026-11-22）

这份文件记录一次真实 OpenAI 兼容接口的验收：上传 → 检索 → `/ask` → `/ask/stream`，
以及 12 题小评测的逐题结果。离线 30 题评测（脚本化模型）仍是回归基线，见 `eval/report.md`。

## 0. 边界

- **语料**：只上传 `eval/demo_docs/` 里的三篇合成演示文档（员工手册 / 信息安全规范 / 差旅制度），
  不涉及任何真实内部资料。
- **凭据**：只从进程环境变量 `LLM_BASE_URL` / `LLM_API_KEY` / `LLM_MODEL` 读取；仓库里没有 `.env`、
  没有 key，本文件与 `eval/real_*` 里也不写 base URL。
- **模型**：`deepseek-chat`，`temperature=0`，`max_tokens=512`。
- **复跑**：`python eval/run_llm_eval.py`（未配置时打印 `REAL_LLM: SKIPPED_NO_KEY` 并退出 0）。

## 1. 冒烟：上传 → 检索 → /ask

| 步骤 | 结果 |
|---|---|
| `POST /documents/upload` × 3 | 全部 `201`，每篇 1 个 chunk（323 / 287 / 242 字节） |
| `POST /search {"query":"年假 10 天"}` | `handbook.md` 第 1–13 行，`chars 0–133`，`score=0.484`，`overlap=1.0` |
| `POST /ask {"question":"年假有多少天，没休完怎么处理"}` | `200`，770 ms，`refused=false` |

答案与引用：

```
answer  : 年假有 10 天 [1]。未休完可结转至次年一季度 [1]。
citation: [1] handbook.md 第1-13行  chunk_id=1  quote=133 字（等于 chunk 全文，是其前缀）
```

**人工对照**（逐字检查被引 chunk）：
被引 chunk 原文是

```
员工年假 10 天，需提前一周申请，未休完可结转至次年一季度。
```

答案里的两个结论（“10 天”“未休完可结转至次年一季度”）都能在这一段里逐字找到；
行号 1–13 覆盖这两句，`quote` 是 chunk 的前缀，`chunk_id` 在库里能查到同一条记录。
结论：**答案正确、文件名正确、行号正确、引用片段确实支持答案**。

## 2. /ask/stream

真实模型下的事件流：

```
status  : 200
events  : citations -> token × 9 -> done
tokens  : 年假 10 天 [1]。
终态    : done {"refused": false}
citations 事件: 1 个候选（handbook.md 第1-13行）
```

**候选引用 vs 最终引用校验**：

| | `POST /ask/stream` 的 `citations` | `POST /ask` 返回的 `citations` |
|---|---|---|
| 内容 | 本次检索到的 1..n 段候选，先于模型输出下发 | 只包含答案里合法 `[n]` 指向的段 |
| 是否校验 | 否（流式输出无法在流中判定 `[n]`） | 是：越界 / 缺失 / 非法格式一律降级为拒答 |
| 用途 | 立刻展示“答案会用哪些片段” | 作为可核验的最终引用 |

要拿“经过校验的引用”，用 `/ask`；`/ask/stream` 只保证“这些片段被展示给了模型”。

**上游失败时的表现**（同一进程内注入错误 key 验证）：

| 场景 | `/ask` | `/ask/stream` |
|---|---|---|
| key 无效（上游 401） | `502` `{"detail":"LLM returned HTTP 401"}`，响应里不含 key | `200` + `citations` → `error{"message":"LLM returned HTTP 401"}` → `done{"refused":false}`（流已开始，错误以事件下发） |
| 未配置 `LLM_*` | `503` | `503`，在开流**之前**返回，不会先 200 再断 |

## 4. 复现的问题与一轮小修复

**复现**：首轮 12 题里，`r02` 的答案是
`差旅报销在财务受理后 5 个工作日内到账 [1]。` —— 原文只写“财务在 5 个工作日内到账”，
模型自己补了“**财务受理后**”这个流程条件。指标仍是 4/4（关键词都命中），但这属于**超出片段的润色**，
正是引用型问答最该防的一类“看起来对”的错误。

**修复**：在 system prompt 里加一条约束——

> 只写片段里有的信息：不要补充片段没有的条件、流程、主体或数字，也不要做片段之外的推断。

**同批题复跑对照**（同一模型、同一批 12 题、同样 3 篇文档）：

| # | 修复前 | 修复后 |
|---|---|---|
| r01 | 员工年假为 10 天 [1]。未休完的年假可结转至次年一季度 [1]。 | 年假有 10 天 [1]。未休完可结转至次年一季度 [1]。 |
| r02 | 差旅报销**在财务受理后** 5 个工作日内到账 [1]。 | 差旅报销财务在 5 个工作日内到账 [1]。 |
| r04 | 一线城市住宿标准**为**每晚 600 元 [1]。 | 一线城市住宿标准每晚 600 元 [1]。 |
| 其余 9 题 | 不变 | 不变 |
| 指标 | 4/4 · 4/4 · 8/8 | 4/4 · 4/4 · 8/8 |

修复后 r02 不再出现“财务受理后”，三处改动都是把答案收紧到原文；指标没有变化，也没有引入新的失败。

## 5. 剩余问题（没有被这 12 题覆盖）

- **答案措辞**：r02 复跑后是“差旅报销财务在 5 个工作日内到账”，忠实但读起来生硬；没有做语言质量评测。
- **引用粒度**：`quote` 取 chunk 前 200 字，而演示文档一篇只有 1 个 chunk，所以引用等于整段；
  真实语料里若一个 chunk 含多条信息，引用无法精确到句。
- **流式不校验**：`/ask/stream` 的 `citations` 是候选，`[n]` 合法性只有 `/ask` 检查（见第 2 节）。
- **拒答依赖模型**：near_miss 的 8 条拒答是模型配合 prompt 的结果；换一个更“爱发挥”的模型，
  可能出现 `refused=false` 但引用合法的情况（引用正确 ≠ 回答正确）。
- **规模**：12 题、3 篇合成文档、一个模型，不构成模型能力评测，只说明这条管线在这个范围内可用。
